# Source-First 逐句阅读协议

## 目的

本协议用于训练“跟着论文原文一步一步建立问题模型”的能力，而不是在知道全文结论后做事后总结。

默认粒度是：

```text
一篇论文
→ 一个小节
→ 一个段落
→ 一个 SentenceUnit
→ 一次只推进一个解释层
```

## 核心规则：禁止未来上下文倒灌

首次顺序阅读处于位置 `N` 时，只允许使用：

```text
已揭示 SourceUnit 1..N-1
+
当前 SourceUnit N
+
Session 明确允许的既有背景知识
```

禁止使用：

```text
SourceUnit N+1..end
```

包括禁止：

- 用后文结论解释作者“此时一定在想什么”
- 因为知道最终机制而强化当前句意图
- 提前透露下一问、下一设计或下一实验结果
- 用全文摘要给当前预测打分

## 为什么必须 no-lookahead

真实研究和设计过程是增量的。

如果阅读者总是先看到结论，再回头解释前文，容易得到：

```text
结局已知
→ 前文看起来理所当然
```

而训练目标是：

```text
有限信息
→ 建立当前模型
→ 形成候选下一步
→ 新信息到来
→ 更新模型
```

这更接近真正解决未知问题时的状态。

## 一个句子的默认拆解顺序

对当前 SentenceUnit，不一次把所有内容讲完。

建议逐层推进：

### 第 1 层：字面含义

回答：

> 这句话直接说了什么？

只做必要释义，不提前扩展完整背景。

### 第 2 层：与前文关系

回答：

> 为什么它接在这里？它与上一句 / 当前段落是什么关系？

常见关系：

```text
continue
clarify
contrast
cause
constraint
example
counterexample
problem
assumption
decision
consequence
evidence
boundary
transition
```

### 第 3 层：新增信息

回答：

> 当前问题模型新增了什么？

可能是：

- 一个新事实
- 一个假设
- 一个限制
- 一个目标
- 一个失败模式
- 一个设计选择
- 一个证据
- 一个边界

### 第 4 层：为什么现在需要这一步

回答：

> 如果只知道此前内容，是什么压力或缺口推动作者走到这里？

这里学习的是“箭头”。

### 第 5 层：当前状态更新

把当前理解写成简短状态：

```text
我们已经知道什么？
当前主要问题是什么？
有哪些约束？
哪些问题仍然开放？
```

### 第 6 层：预测下一步

在读取下一句以前，尝试：

```text
下一步可能处理什么？
有哪些合理分支？
什么约束会影响选择？
```

Prediction 不要求命中作者。

## AI 行为

Learning Mode 下，AI 应：

- 一次只揭示当前 SentenceUnit 或明确的最小 reveal group
- 只使用允许的历史上下文
- 一层一层解释，不一次把后文全部讲完
- 区分原文事实与 Derived interpretation
- 明确指出“看到什么 cue，激活什么问题结构”
- 如果当前文本不足以证明作者意图，使用“可能 / 更像 / 当前可推测”而不是断言
- 在自然学习边界停下
- 用户说“下一句”时才推进 Source position

AI 不应：

- 因为知道整篇论文而提前剧透
- 把自己的预测写成作者原意
- 输出大段不必要的内部 chain-of-thought
- 用知识百科替代当前论文阅读
- 一次生成整节 summary 来绕过逐句学习

## 学习者关注点

第一遍阅读不要求每句都立即背下来。

主要训练：

```text
看见什么？
→ 为什么重要？
→ 它改变了什么？
→ 当前下一步会是什么？
```

如果某句只承担连接、定义或例证作用，不需要强行制造深层机制。

## 句子不是绝对边界

以下情况可以使用 reveal group：

- 公式把一句自然语言拆开
- 引文或脚注导致句法不完整
- 一个定义必须与紧邻下一句联合才能构成最小有用单元
- PDF 转换造成错误断句

规则：

```text
最小有用输入 > 机械逐句
```

但任何合并都必须：

- 保留原始顺序
- 记录包含哪些 SentenceUnit
- 不借机跨过自然推理边界

## 前置知识使用规则

No-lookahead 不等于“禁止使用所有已有知识”。

允许使用学习者已经拥有的背景知识，例如操作系统、数据库、数学基础。

但必须区分：

```text
Source 当前证明了什么
vs
我因为既有知识还知道什么
```

如果既有知识来自同一论文的未来部分，则首次 Session 中不可使用。

## Retrospective Mode

读完整篇后可以重新回看早期句子，并使用全文理解：

```text
retrospective = true
```

这时可以分析：

- 早期伏笔后来如何展开
- 一个术语后文怎样被精确定义
- 一个早期约束最终影响了什么机制

但必须明确：

> 这是知道全文后的回顾，不是首次阅读位置 N 当时能够确定的结论。

## 多遍阅读建议

### Pass A：理解原文

```text
逐句
→ 字面
→ 关系
→ 新增信息
```

### Pass B：学习推理结构

```text
problem
→ constraint
→ decision
→ consequence
```

### Pass C：Prediction

遮住下一句，预测合理方向。

### Pass D：Recall

只看 cue 或问题，重建关键连接。

### Pass E：Reconstruction

按小节或整篇重建：

```text
Problem
→ Constraints
→ Alternatives
→ Decisions
→ Mechanisms
→ Trade-offs
→ Evidence
```

### Pass F：Transfer

把同一思考结构应用到新问题。

Pass 不是永久状态机，只是建议的学习视角。

## 一个最小交互示例

当前已揭示：

```text
系统需要处理规模持续增长的数据。
单个节点的容量不足以满足需求。
```

此时不应该直接跳到作者后文方案。

当前可建立：

```text
数据规模增长
→ 单节点容量成为约束
→ 需要跨多个节点承载数据
```

然后停下来预测：

```text
下一步可能要解决：
数据如何划分？
数据如何定位？
节点变化时如何处理？
```

再揭示作者下一句。

重点不是预测一定命中，而是让自己的问题模型变得可观察、可修正。

## 核心不变量

```text
上下文只能向前增长。
当前解释不能依赖未来 Source。
事实与解释分开。
预测与作者事实分开。
第一次阅读与回顾阅读分开。
一次只加深一点。
最终训练的是可迁移的思考结构，而不是 AI 文本记忆。
```
