# Source-First 逐句分析协议

当前契约：`source-first-analysis/v2`。唯一目标是提供基于已知信息、逻辑连贯、层层讲透的 AI 逐句分析，让用户通过持续阅读自然学习分析方法。

## 唯一日常流程

```text
当前原文 → 忠实释义 → 有依据的连贯分析 → 当前句结束
```

用户无需作答或刻意练习。本仓库已删除训练模式、题目、评分、预测锁定及盲测流程，不保留可选训练入口。复杂度放在 AI 分析的认真程度上，不放在用户操作上。

## 分析必须做到什么

**先说清对象和字面意思。** 原文先行，外语随后给忠实中文翻译；中文原文不重复翻译。保留“可能、通常、仅在”等限定。首次必要术语就地解释，指代不让用户猜。翻译不夹带自己的机制解释。

**关系要具体。** 联系必要的已读前文，指出当前句在哪个地方承接、对比、回答或限制前文；不能只贴“因果、转折、解耦”等标签。读者不应为理解当前分析而自行翻找大段旧解释。

**逐层承接，不跳步。** 从当前原文和必要前文出发，先澄清对象与线索，再解释所需的前提或区别，最后得到当前结论；后一层使用前一层已经说明的信息。每层解决一个真实的理解疑问，不罗列互不衔接的结论。重要推导说明“为什么能从这里走到那里”，额外前提显式提出；不能用“显然”“本质上”或一根箭头跳过理由，不能把先后顺序说成因果。

这里的“详细”是把依据、必要前提和关键连接讲完整，而不是增加无关背景；不能用翻译、结论或术语标签替代这段显式推导。结论是推导后的收束，不能把中间理由留给用户补。信息不足时，讲清缺少什么及为何暂不能继续推导，不补造答案。

**每句有真实增量。** 说明当前多知道了什么、修正了什么，或仅起什么结构作用。普通过渡简短，关键机制讲透；不强迫每句生成完整机制链、L0/L1/L2 标签或“思维方法总结”。方法自然体现在分析里。

**边界清楚但不做报表。** 原文明说、有限推论、尚未确定分别用自然语言交代即可，不要求每句列三栏。每个重要箭头须能追到已读 Source 或注明推论及其条件。不要为了读起来流畅而编出作者动机、隐藏困难或关闭开放问题。

**让理解顺畅。** 用连贯短段落和必要箭头，不堆标题、术语或重复总结。主动补齐必要连接，不让用户再猜指代、补前提或翻找上下文；删去无助于当前理解的背景。简单的是阅读流程，不是被压缩的推导。方法体现在具体分析中，不再追加练习。目标是减少可避免的理解摩擦，不隐藏材料本身的困难，也不把阅读流畅当作能力提升证明。

呈现顺序可自然调整。默认只需要“位置/原文、翻译、分析”，结尾给一行简短位置即可；完整 hash、工具参数和检查清单留在状态记录中，不要求用户阅读。

## 完整推导示范（虚构）

以下两句话是自包含的虚构材料，不是 Kafka 或任何论文原文，不引入真实阅读的未读信息。示范只解释上面的 v2 要求，不是固定层数、字数或每句必须套用的模板。

已知前文：

> 每发起一次请求，都会产生固定开销 C（C > 0）；这项开销不随该请求携带的记录条数变化。

当前句：

> 客户端可以在一个请求中提交多条记录。

只说“这是批处理，可以提高性能”，就省略了这两句话之间最重要的连接。下面从已有信息展开，不先给出未经限定的性能结论。

**先看，前文把开销和什么联系起来。**

前文说的是“每次请求”，不是“每条记录”。所以，要计算这项开销发生多少次，应当先数请求次数，而不能直接数记录条数。记录本身可能还有处理成本，但前文给出的 C 只代表请求的这一项固定开销，两者不能混在一起。

**接着看，当前句改变了哪一项。**

“一个请求中提交多条记录”没有说待提交的记录变少了，也没有说记录不再需要处理。它允许改变的是这些记录怎样分配到请求中。因此，需要比较的是：完成相同记录提交，是否能够使用更少的请求。

为看清这一点，取同样三条记录甲、乙、丙，假定它们可以合在一个请求中提交。这是说明用的比较假设，不是从当前句推出任意记录都能合并。

分别提交时，三个请求各携带一条记录；合并提交时，一个请求携带全部三条。两种方式提交的记录相同，变化的是请求次数：三次变为一次。

**再把这个变化接回前文，而不是直接跳到“更快”。**

前文已给出每次请求的固定开销 C，并说明它不随记录条数变化。因此，分别提交时，这项开销的总量是 `C + C + C = 3C`；合并提交时是 `C`。减少的是重复发生的请求固定开销，不能把它误说成每条记录自身的处理工作也减少了。

**现在才能说明，“摊薄”具体意味着什么。**

分别提交时，每条记录独自承担一次 C，平均固定成本为 C；合并提交时，三条记录共同承担一次 C，平均固定成本为 `C / 3`。这项开销没有消失，而是由多条记录共同承担；由于 C > 0，在这个比较中每条记录分摊的这一部分成本确实降低了。

所以，当前能够得到的结论是：在记录可合并、请求固定项不随记录数变化的条件下，把相同记录合到更少请求里，可以减少重复发生的固定开销，并降低平均到每条记录上的这部分成本。

**最后检查，结论还能扩大到哪里。**

两句话没有给出其他处理成本、合并产生的额外工作或等待时间。因此，这个推导只能解释固定开销这一项，不能证明总处理时间一定更短、每条记录的延迟一定更低，也不能确定最佳批量大小。这些不是用“提高性能”四个字就能补齐的信息。

这段示范的关键是保持依据与连接完整：辨认开销对象，保持比较的记录相同，找出请求次数的变化，再按已有条件推导固定项成本，最后限定结论。实际分析中，只展开当前理解真正需要的连接；删去重复，不删去成立所需的理由。

## 输出前的小检查

AI 在输出前检查：原文是否忠实？关键判断的依据和连接是否完整？有没有越过已知范围？有没有可以删掉的重复或含糊表达？发现问题就在当前解释中修正，不把自检表发给用户，不另开评分或验收任务。

用户说“没理解”时，优先修复遗漏前提、抽象术语、层次混淆或表达跳步；不要改成考用户。澄清只使用已读范围，不把追问视为推进下一句的授权。

## Source 边界

普通首次阅读只用已揭示前文与当前单元。必要的通用概念可以在明确允许的背景范围内说明，但不能据此替代目标论文事实。现代版本对照或外部检索须另获授权，和当前论文分析分开。

一次“下一句”默认取得一个 canonical SourceUnit，并精确回读。保留 provider 的 kind、顺序、fragment 和 locator；不根据标点自造新 identity，不为凑完整句批量读取后文。图表或公式只在当前内容确有需要时核对原始视觉；无法避免越界暴露时停止并记录，不能假装没看见。

原文返回不完整、identity 不符或 locator stale 时，不用记忆、搜索或二手分析补齐。工具细节按需查 [reading-mcp 集成](../integrations/reading-mcp.md)，不是每句的额外前置阅读。

## 连续阅读与范围

本句讲完只停止本次输出；同一会话中下一次“下一句”即可继续当前已授权范围。追问、换说法、回看不改变已揭示位置，也不触发重测。默认不新开 Session、不要求换 conversation。

如果下一单元超出已授权范围，简短说明边界并请求继续范围；用户同意后由 Agent 保存范围变化再读。历史停点、已消费的一单元授权不被本协议自动重新激活。

暂停、自然段落/机制收束、交接、故障或范围变化时保存 [一份阅读状态](reading-sessions.md)。操作位置与分析摘要可以分区保存在同一记录；只有摘要确实过长时才拆出一份引用式资产。

## 版本与历史

v2 删除 v1 保留的可选训练入口，并强化逐层承接。旧 Profile / Pilot 已从当前文件树移除；历史字节和结果仍在原 commit，索引见 [历史引用](../README.md#历史引用)。旧绑定按记录的 commit + path 读取，不要求恢复已删除文件或重跑旧流程。

新 Session 记录本契约 id 和来源 commit。旧 Session 在用户授权采用新流程时，只需在同一阅读状态记一次 `旧绑定 → source-first-analysis/v2`、生效 locator 和来源 commit；Source identity、已读位置、未知项和范围保持不变，不要求重读或 fresh 测试。用户目标决定当前授权，不允许静默改写既有记录。

CI 只检查结构；这份契约是否落实，直接在真实逐句分析中看误读、跳步、冗余与边界，按具体问题修正。正常阅读不设额外准入验收。
